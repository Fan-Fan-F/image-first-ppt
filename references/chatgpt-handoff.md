# 在 ChatGPT 网页版准备逐页清单

在 ChatGPT 网页版单独进行图片生成或清单提取，下载结果后交给 Codex。网页版所用的模型、工具及配额以账号显示为准。以下是手工交接，上传前可删去与本页无关的材料。

## 可选的生图提示词

一次先生成一张有代表性的整页设计图。确认它的视觉方向后，让后续各页使用同一风格、画幅和排版规则。下面方括号替换为实际内容。

```text
生成一张 [16:9] 的单页 PowerPoint 视觉设计稿。主题为 [主题]，面向 [受众]。
本页文案是 [逐项粘贴准确文案]，按 [标题、正文、数据、图片说明] 布局。
视觉方向为 [颜色、网格、版式、插画风格]。保留足够留白、行距和图文间距。
让文字落在平坦、干净的区域内，让可移动的图标、图片和卡片边缘尽量清晰。
重要照片、标志或图表有参考附件时保留其内容。不要添加未经提供的标签、数字或装饰性文字。
只返回整页图片。
```

将下载的设计稿保存为本页原图。后续使用同一个原始文件作为坐标和视觉参考。先从文件属性取得像素宽高，避免用网页预览尺寸。

## 默认提示词：清点元素并返回 JSON

上传从 `init` 得到的单张原图，可另附准确文案、图标或照片原件、可用字体名称。复杂页面可再附 `source_guides.py` 生成的带坐标裁片。把下文中的文件名、页 ID 和宽高改成实际值。

```text
按原图逐项登记这一页，输出一个有效的 UTF-8 JSON 对象。文件名为 s001-inventory.json。
页 ID 为 s001，原图文件名为 s001.png，宽 [1920] 高 [1080] 像素。
原点在左上，向右和向下为正。box 写 [x,y,width,height]，右边和下边不包含在框内。
若参考了裁片，先把文件名里的 x/y 偏移加回去，再输出原图坐标。
elements 按原来的叠放顺序从底到顶，每项用唯一 ID。

先分区巡检，然后再对照整页核一次。逐个保留卡片、图标、照片、徽标和有意义的装饰。
逐行核对标题、副标题、正文、图例、坐标轴、页脚、数字、标点、脚注及可读装饰标签。
内容可完整排版的文字登记为 text，并使用原文。若原图与附带定稿冲突，按定稿录入并写入 review。
形状规则且能可靠匹配的登记为 shape。无法可靠重建的形状登记为 image，并保留原图裁切区域。
复杂图形和照片登记为 image，给出完整可见区域。一个对象里的断开笔画、零件和小装饰仍归同一 ID。
为分层给出原图坐标。两个重叠对象应分别登记，按挡住与被挡住的关系排列。确实不能可靠拆开时，
登记一个完整的图像组，在 review 写出包括哪些元素、遮挡范围及拆分限制。连续底纹保留在背景。
polygon 为 image 的原图像素顶点 [[x,y],...]，只在能可靠沿物体轮廓定位时提供。
erase 为原始文字占据的像素框 [x,y,width,height]，它可与新的文字框 box 不同。
erase_polygon 用原图坐标圈定明确可清除的字形区域，避免波及图标、边框和其它文字。
文字颜色用 #RRGGBB，font_px 用原图像素给出预计字号；font 和 font_ea 仅在能给出合理候选时填。
若有多种字号、颜色或字重，记录到 review 或按实际分段登记。低置信度文字、边界、字体或叠放关系都
写入 review 并注明元素 ID。无法读出的字符不要编造。
清点环节只输出 JSON。不要生成、修改或重画图片，不要重新排列组件，不要返回 PowerPoint。

格式示例（ID、坐标、文案、字体和颜色均为演示）：
{
  "id": "s001", "source": "s001.png", "width": 1920, "height": 1080,
  "elements": [
    {"id":"img01","kind":"image","box":[1140,230,540,560],
     "polygon":[[1140,280],[1679,230],[1679,789],[1140,789]]},
    {"id":"card01","kind":"shape","box":[120,350,520,170],
     "shape":"rect","fill":"#E9F0F7"},
    {"id":"txt01","kind":"text","box":[120,100,910,80],"text":"项目进展",
     "font":"Arial","font_ea":"Microsoft YaHei","font_px":64,"color":"#133551",
     "bold":true,"align":"left","rotation":0,"erase":[122,115,289,64]},
    {"id":"txt02","kind":"text","box":[126,864,420,36],"text":"当前进度 85%",
     "font_px":27,"color":"#133551","align":"left",
     "review":"低置信度：复核原图中的百分比。"}
  ],
  "review":["img01 右下边缘与背景接近，蒙版需放大核对。"]
}
```

保存 JSON 后交给 Codex 核对。网页视觉识别给出的坐标和字体是候选值。Codex 会用本地原图和渲染结果核定边界、文字内容、字形宽高和颜色。优先利用原图像素裁切可移动素材。

## 只修有问题的小块

有了渲染结果就一并附上原图、待修裁片，以及标出差异的局部图。对漏件先补清单，对形变先改边界和轮廓，对错字先改文本。只在字形清除或拆层留下难以恢复的背景时请求补画。

```text
附件分别是本页原图、当前渲染、标注过的差异图和待修裁片。只处理元素 [ID] 的局部问题 [描述]。
1. 对照原图与当前渲染，先列出该区域缺失、位移、形变和文字样式偏差。
   给出受影响元素 ID 和建议更改的 JSON 字段。请保留已正确的其它元素和位置。
2. 仅当我明确要求修复像素时，针对原图区域 [x,y,width,height] 返回同宽高 PNG。
   只补我标出的遮挡洞或被清除的字形。沿用边缘颜色、结构、纹理和光照。
   不要移动、拉伸、重画已有可见元素，也不要补字、改变文字字号或新增装饰。
3. 补图请同时说明原图坐标和实际输出像素宽高。若分辨率或定位无法保证，就说明不确定之处。
```

把补图放在清单目录内，通过 `erase_patch` 或 `underlay_patch` 引用。本地合成只采用核准遮罩内的修复像素。输出偏移、尺寸不符或改变附近线条时，先调整遮罩和裁片并重新核对。图层有真实透明通道时，仍应对照原图检查轮廓、孔洞、阴影和边缘像素。
